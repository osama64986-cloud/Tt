# نبض NABD — موقع مودات ماين كرافت

موقع بستايل ماين كرافت لنشر **المودات، إضافات البيدروك، التكسترات، الشيدرات، الخرائط والعوالم**.
الزوار يتصفحون ويحمّلون فقط، وأنت وحدك تقدر ترفع وتعدّل وتحذف من **لوحة التحكم** (`admin.html`) من المتصفح أو الجوال، بدون برمجة.

## التشغيل لأول مرة (مرة وحدة بس)
1. **ادمج هذا الفرع في `main`.**
2. Pages يشتغل من فرع `gh-pages` اللي ينبني تلقائياً (لا تعدّل عليه يدوياً).
3. في المستودع: **Settings ← Actions ← General ← Workflow permissions** واختر **Read and write permissions** واحفظ.
4. سوّ مفتاح دخول: [صفحة إنشاء مفتاح](https://github.com/settings/personal-access-tokens/new)
   - Repository access: **Only select repositories** ← هذا المستودع بس.
   - Permissions: **Contents = Read and write**، **Actions = Read and write**.
   - Expiration: 90 يوم (ولما ينتهي سوّ واحد جديد).
5. افتح `https://osama64986-cloud.github.io/Tt/admin.html` وادخل بالمفتاح.

## الرفع
- اضغط **➕ رفع عمل جديد**، عبّي البيانات، واختر الملف (حتى **95MB**) والصور.
- الموقع يرفع الملف، ثم GitHub Actions يسوي **Release** فيه الملف، ويحدّث `mods.json` والصور، ويعيد نشر الموقع لحاله. العملية كلها تاخذ تقريباً دقيقة إلى دقيقتين.
- الملفات الأكبر من 95MB: اختر **رابط خارجي** (MediaFire، CurseForge، Modrinth، أو Release ترفعه يدوياً).
- عدد التحميلات لكل عمل يظهر تلقائياً من إحصائيات Releases.

## كيف يشتغل
```
admin.html ──(مفتاحك)──► GitHub API: يرفع الملفات لفرع مؤقت inbox/...
                          └─► يشغّل publish.yml
publish.yml ──► scripts/publish.py يفحص كل البيانات
             ──► gh release create (الملف)
             ──► يحدّث mods.json + images/ على main
             ──► يحذف الفرع المؤقت ويعيد نشر الموقع (pages.yml)
```

| الملف | الوظيفة |
|---|---|
| `index.html`, `assets/app.js` | الموقع العام |
| `admin.html`, `assets/admin.js` | لوحة التحكم |
| `assets/common.js` | دوال مشتركة (تنظيف النصوص والروابط) |
| `mods.json` | قاعدة البيانات (تتعدل تلقائياً) |
| `scripts/publish.py` | التحقق والنشر، ويشتغل على GitHub |
| `.github/workflows/` | النشر التلقائي |

## الظهور في Google
- كل عمل له صفحة خاصة `m/<id>/` فيها عنوان ووصف وصورة وبيانات منظمة (JSON-LD)، وكلها تنبني تلقائياً.
- `sitemap.xml` ينبني تلقائياً. سجّل الموقع في [Google Search Console](https://search.google.com/search-console) وأرسل الـ sitemap.
- كود التحقق من Search Console تحطه من لوحة التحكم ← ⚙ إعدادات الموقع.

## التحمّل والضغط
- الموقع ملفات ثابتة على شبكة GitHub (CDN)، فآلاف الزوار بنفس الوقت ما يأثرون عليه.
- ملفات المودات على Releases، فما تنحسب من حد الـ 100GB الشهري للموقع.
- عدد التحميلات ينحسب كل 6 ساعات في `stats.json`، فالزوار ما يضغطون على GitHub API.

## الأمان
- لوحة التحكم ما فيها أي أسرار. بدون مفتاح عنده صلاحية كتابة على المستودع ما أحد يقدر يغيّر شي، و**GitHub نفسه هو اللي يمنع** مو كود الموقع.
- كل النصوص تنعرض كنص، فما أحد يقدر يحقن كود (XSS)، والروابط تُقبل `https://` فقط.
- سياسة أمان (CSP) تمنع تشغيل أي سكربت من خارج الموقع.
- `publish.py` يعيد فحص كل شي على السيرفر: المعرّف، النوع، الأطوال، الروابط، نوع الصور الحقيقي، والمسارات.
- الـ workflow ما يدخّل المدخلات مباشرة في أوامر الشل.

- «تذكرني» يحفظ المفتاح **مشفّراً** (AES-256 + PBKDF2) بكلمة سر منك، ولا ينحفظ أبداً كنص مكشوف. واللوحة تنقفل لحالها بعد 30 دقيقة بدون استخدام.
- مفاتيح Classic (`ghp_`) مرفوضة، والمقبول بس Fine-grained محدد على هذا المستودع. والمفتاح ما يقدر يعدّل ملفات الـ workflows لأنه ما عنده صلاحية Workflows.
- يُقبل رفع ملفات ماين كرافت بس (`.jar .zip .mcaddon .mcpack .mcworld .mctemplate .7z .rar`)، ويتأكد إن الملف فعلاً أرشيف، فما ينقبل `.exe` حتى لو انسرق المفتاح.
- كل ملف ينحسب له **بصمة SHA-256** وتظهر في صفحته، فالناس يقدرون يتأكدون إن الملف أصلي.
- إضافات GitHub Actions مثبتة على بصمات (SHA) محددة، وDependabot يحدّثها.

**وصاياك:**
1. فعّل **التحقق بخطوتين (2FA)** على حساب GitHub، فهو أهم حماية.
2. لا تشارك المفتاح، ولا تفعّل «تذكرني» على جهاز مو لك.
3. إذا شكّيت إن المفتاح تسرّب: احذفه من [صفحة المفاتيح](https://github.com/settings/personal-access-tokens) وسوّ واحد جديد.
4. كل مواقع GitHub Pages على حسابك تشترك في نفس النطاق (`osama64986-cloud.github.io`)، فلا تنشر على حسابك مواقع فيها سكربتات من مصادر ما تثق فيها.
